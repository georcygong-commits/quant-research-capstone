# 模拟盘与回测/实盘一致性跟踪

在 capstone 端到端多因子策略基础上，搭建一套**回测与模拟共用同一信号引擎**的模拟盘系统，
用于持续跟踪策略表现，并严格验证"回测口径"与"真实持仓口径"是否一致。

## 核心设计思想

回测和模拟盘**不允许各写一份信号逻辑**，否则两者永远无法对账。本系统把数据加载、因子、
特征、模型训练、预测、目标权重全部收敛到 `signal_engine.py` 一个模块：

- 回测路径：`backtest_weights()` / `backtest_returns_bh()` 调用引擎；
- 模拟路径：`tracker` 在每个调仓日调用引擎的 `target_weights_pit()`（PIT，逐点独立生成）。

两条路径若在同一交易日给出相同目标权重，即证明信号无分叉、无前视偏差。

## 模块结构

| 文件 | 职责 |
| --- | --- |
| `signal_engine.py` | 数据加载、四因子、截面标准化、`X_full`（完整特征）与训练样本、年度 walk-forward 模型缓存、全样本预测、回测权重、固定权重与 buy-and-hold 两套回测、PIT 信号 |
| `paper_broker.py` | 份额 + 现金记账，按目标权重调仓、扣双边成本，每日收盘 mark-to-market |
| `tracker.py` | 逐日驱动，月末调仓、日频记录，增量写入 `state/paper_trading`，支持断点续跑 |
| `consistency.py` | 权重 / 日收益 / 净值三层对账，阈值判定，输出绩效摘要与 `consistency.csv` |

## 关键口径说明

1. **两种净值口径**
   - **固定权重（capstone 向量化口径）**：调仓区间内每日名义权重恒定，隐含每日再平衡；
   - **buy-and-hold（真实持仓口径）**：调仓后份额固定，权重随个股涨跌漂移。
   真实/模拟账户是 buy-and-hold，因此一致性检验以 `backtest_returns_bh()` 为主对账基准；
   固定权重口径仅作对照，两者在月内的差异是已知的"权重漂移"，不是 bug。

2. **成本预留，杜绝隐形杠杆**：调仓时先估算换手成本，按"扣成本后的可投资金"分配份额，
   保证调仓后现金非负、持仓权重和恒为 1，避免成本占用累积成隐性杠杆（与 B13 修复的
   `target.ffill()` 杠杆问题同一类隐患）。

3. **完整特征 `X_full`**：实盘预测只需要因子、不需要当日标签。`X_full` 保留所有可计算
   特征的日期（含数据末尾），训练样本才与需要未来 5 日收益的标签取交集。

4. **启动边界**：模拟盘在启动日（2024-01-31）从全现金首次建仓，而回测在该日是从旧仓再
   平衡，两者总资产基数不同，启动日存在一次性差异（约 0.34%），在首个常规调仓日
   （2024-02-29）后即收敛。一致性检验对启动边界单独量化，不纳入稳态严格判定。

## 运行方法（手动）

初始资金 1,000,000，月频调仓、日频记录，回放起点 2024-01-31。

```powershell
# 1) 交易日先更新本地数据（Wind 在线时）
python run_daily.py --dump-mode update

# 2) 推进模拟盘（断点续跑，只处理新增交易日）
python -c "from paper_trading.tracker import run_tracker; print(run_tracker())"

# 3) 运行一致性检验
python -c "from paper_trading.consistency import run_consistency; r,s=run_consistency(); print(r); print(s)"
```

## 状态文件（`state/paper_trading/`，已被 .gitignore 排除）

- `nav.csv`：每日模拟净值、总资产、日收益、回测/基准净值、换手与成本；
- `positions.csv`：每日非零持仓的权重与份额；
- `trades.csv`：每次调仓的目标权重；
- `meta.json`：启动日、初始资金、现金、最后处理日期；
- `consistency.csv`：最近一次对账结果。
